## Koe icon: two people and AI

The app icon uses three overlapping, offset speech bubbles: a white **A**, a mint **AI** in the middle, and a dark-blue **文** on the frontmost layer. The original Koe palette is retained: blue `#2458CC`, white, mint `#8AD9BF` and navy `#153A78`. All three labels are vector paths, so iOS does not need a matching font. The scalable [app icon](Koe-Maui/Resources/AppIcon/appicon.svg) and [launch graphic](Koe-Maui/Resources/Splash/splash.svg) share the same foreground geometry and stacking order. The app icon has a full square, opaque background; iOS supplies its mask. The launch graphic uses rounded corners on the existing light splash background. A full-resolution RGB [PNG export](store-assets/Koe-Icon-1024.png) is included for previews and future store artwork. Updating the installed icon requires a new build.

## Saved conversations and grouped Settings

Saved chats are shown directly in the normal Koe window, inside the transcript area. The Koe header, account status, model picker and the full composer stay visible. Tap the **square-and-pencil** icon in the header for a new conversation, tap a saved chat to open its transcript in the same area, and use the back chevron to show the embedded list again. There is no separate start page or chat-list navigation push. Typing or recording from the list starts a new conversation using the visible composer. Each row shows a title from its first message, the latest message or draft, its language pair and its date. Swipe left to reveal the red **Delete** action, then tap it to delete that conversation and its photos. **Clear history** has been removed. New, unused chats do not create empty list entries.

Completed translations, bilingual AI messages, transliterations, source links, selected languages, active speaker/AI mode, editable drafts and attached photos are stored in the app's data directory. Text changes are saved after a short debounce; sending, leaving a chat and app lifecycle events also flush the current snapshot. Opening a chat restores its own messages and therefore its own AI context. A new chat starts with no prior conversation context. Opening the list or starting another conversation pauses an active microphone and saves the current draft first; recording never restarts automatically on reopening.

A per-chat JSON manifest is written to a temporary file, flushed and atomically renamed. The last valid manifest is retained as a recovery backup. Photos are stored separately by content hash inside the chat folder, rather than copied into every message or JSON rewrite. Deleting a chat removes its manifest, backup and photos; queued saves cannot recreate that deleted chat. Credentials and personal voice API keys remain in SecureStorage and are never included in chat files. Paths are reconstructed from AppDataDirectory on each launch. This is device-local chat storage, not a new account or app-provided cross-device sync. Existing conversations that were already lost by older builds cannot be recovered.

The header uses bundled vector icons: a chevron in a round back button, plus square-and-pencil and ellipsis buttons in a shared rounded capsule. The icon colors follow Koe's light blue palette. New-conversation behavior, draft saving and swipe deletion are unchanged.

**Settings** now opens a grouped sheet with rounded cards, a centered heading, a Done button, text-size checkmarks and a transliteration switch. Language selection, iPhone voice selection, optional OpenAI voice setup, usage and sign-in/sign-out remain accessible. Colors adapt to the device's light/dark appearance; the OpenAI key/setup sheet uses the same readable grouped style. The **Account and billing** group lists **Manage usage**, then **OpenAI voice** (API key, voice and billing setup), then sign-in/sign-out. The ChatGPT login and API-cost consent for optional OpenAI speech are retained.

Validation covers restart recovery, Unicode, photos, drafts, independent chats/languages, AI source metadata, sorting, deletion, queued saves, corrupt/partial manifests and future-format preservation. Native iPhone layouts, keyboard behavior, background/resume and left-swipe deletion still require a TestFlight check. No updated App Store screenshots have been created for these UI changes yet.

## Automatic web search in AI mode

AI requests include the hosted `web_search` tool and `tool_choice: auto`. The model is instructed to search for current facts, prices, opening hours, local recommendations, source links and explicit verification, while ordinary conversation can answer directly. The device date helps interpret relative dates; no device location or GPS permission is added. Translation requests do not receive the search tool. The existing selected model, ChatGPT OAuth token, bilingual JSON schema, language detection, history, transliteration, `store: false` and `stream: true` are retained. There is no new API key or developer-funded search backend.

The app shows “Searching the web …” from search-progress events, and marks an answer “AI · Web search” only after a completed search call is reported. Citation URLs and titles come from `url_citation` metadata in the completed response, not from URLs invented inside generated JSON. Sources are deduplicated and limited to absolute HTTP(S) links without embedded credentials. Both answer labels contain clickable numbered source spans, with matching titles below the bilingual answer; opening a source requires a user tap. Copy and speech playback use the answer text without the app’s source buttons or opaque tool citation markers. Previous source links are included as reference data in bounded AI follow-up context. A searched answer with no citation metadata states that source links were not returned.

Streaming accepts the canonical final assistant message and its citations, so intermediate tool commentary does not corrupt the JSON. Incomplete/failed streams and cancellation do not commit a partial answer or source list. Rejected web requests report a model/account access error; the app does not silently retry without search, select another model, or switch to API billing. Availability depends on the selected model and account/workspace policy, as described in [Sign in with ChatGPT limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations). Tool behavior and citation metadata follow the [official web search guide](https://developers.openai.com/api/docs/guides/tools-web-search).

Validation uses simulated streaming responses for search/no-search, progress, canonical text, sources, cancellation, failures and URL handling. A live request through the iPhone’s ChatGPT session and a TestFlight check are still needed to confirm model access, actual searches and source-link presentation.

## Bilingual AI participant

A small **AI** button sits centered between the two speaker buttons on the same row, without arrows. Tap it to ask the connected ChatGPT model a question by voice, text or photo. The current model picker applies to both translation and AI mode. Tap either language to return to normal conversation translation. Mode changes are disabled while a recording turn is active or a request is processing; the existing pause/resume, editable draft, send and discard controls are shared.

AI mode detects the latest question's language instead of using the last speaker. Typed text and image text are identified in the same bilingual Responses request; no separate detection request is sent. A `first_language` enum restricts the first answer to one of the two selected languages. The detected input language appears first if it matches the pair, followed by the other language. When the language cannot be determined confidently (such as ambiguous short input), or the input is an image without clear text or a third language, the first selected language is the stable fallback. Clearly identifiable short questions still use their detected language first. Regional language codes are resolved only when unambiguous. Metadata and answer order are validated before entering chat history. Follow-ups are detected again independently. AI mode releases the forced speaker keyboard so users can type in either language.

On iPhone, automatic **voice** input now provides a live draft while the microphone is running. One AVAudioEngine tap feeds both a streaming native recognizer (`ShouldReportPartialResults = true`) and a temporary CAF recording. The first preview locale follows the device language when it matches the selected pair, otherwise the first available selected locale; it never uses the last speaker. After the first 2.5 seconds, the live task is finalized and a short recorded prefix is compared with the other selected locale, sequentially. The selected streaming recognizer then receives a replay of the beginning plus any audio captured during the check, before continuing with new buffers. Early wording can change while the language is identified, and a short preview delay is possible during that check. At most one Apple recognition task is active at a time. The audio replay queue is bounded to 12 seconds, and the short comparison is bounded to four seconds per file pass.

Native recognition ending after a silence starts a new streaming segment while retaining previous words. If iOS resets a partial inside the same task without a final event, a two-second gap between text changes checkpoints earlier phrases. New phrases append to that checkpoint; cumulative results and overlapping tails are merged without duplicating the earlier text. Replayed prefixes do not duplicate the draft or make it temporarily shrink to its opening words. Empty callbacks and stale results cannot erase or resurrect text. The live draft remains editable; SpeechDraft protects user edits and deletions from later partial/final recognition. Pausing/sending first waits for the live task’s final words (up to three seconds). When a language has been checked and earlier phrases have been retained across pauses/restarts, the complete live utterance is used directly so a truncated whole-file result cannot overwrite it. Uninterrupted utterances and recordings stopped before the initial language check still use the complete file against both selected locales, with up to 15 seconds per pass. Thus the live preview is provisional, and final recognition can still take longer than fixed-language recording. Cancel/discard stops the microphone, the language check and live tasks, and removes temporary recordings. Cache files left by force-quit are removed on the next service initialization.

On-device recognition is used when available; other locales may use Apple's recognition service as before. No OpenAI audio transcription endpoint, API key or additional API billing is introduced. Normal translation retains its existing single-language live transcription. Automatic voice recognition is limited to the selected pair and can confuse similar languages or dialects. Real-device TestFlight checks are needed for live updates, switching the initial language, longer speech with pauses, recording resume, cancellation, microphone routing, speed and memory. Select a language button to return to fixed-language recording if needed.

Both the question and its answer appear centered in the shared history with an AI label and light green backgrounds. Each answer section keeps its own copy/speaker buttons and transliteration. Text size settings apply to both. Normal translation still switches speakers after sending.

AI mode answers the latest request rather than translating the question. A strict JSON schema returns detected language metadata, two equivalent answer texts and independent readings in a single Responses request. Non-Latin text receives the requested romanization, while Latin-script text and disabled readings remain empty. The source-language question is kept unchanged. Image-only questions ask the AI to describe/help with the photo. Partial answers appear in a temporary preview; the question/answer enter history only after both complete answers have been validated. Failures/cancellation retain the draft and attachment, unless discarded, and do not add a partial or duplicate chat turn.

The public Responses endpoint, current ChatGPT OAuth credential and cached account-specific model catalog are shared with translation. `store: false` and `stream: true` remain in use; no separate API key is required for AI text answers. Recent visible translations are supplied as quoted background and previous AI user/assistant messages support follow-ups. Context is bounded to the latest 16 messages and 20,000 text characters, with at most one historical image plus the current photo. AI context is isolated to the currently opened saved conversation; a new conversation starts with empty context. This is an in-app assistant using the selected model, with automatic web search but no booking or other external action tools, and is not linked to chat history in the ChatGPT app. Model quality, automatic speech capture, language accuracy, recognition latency and native layout need a TestFlight check. Optional OpenAI read-aloud retains its separately configured API billing.

## German (Switzerland)

**Settings → Conversation languages** offers **German (Switzerland)** separately from **German** when iOS reports `de-CH` in its supported speech locales. It is not fabricated when that locale is absent; the Windows development fallback includes it for development. Search also accepts Swiss German, Schweizerdeutsch and Schweiz. The speaker buttons use the shorter **German (CH)** label and the greeting is **Grüezi!**. The saved selection uses the distinct `de-CH` identifier; existing German selections stay `de` with their original preferred `de-DE` recognition locale.

Recording and keyboard selection use the Swiss `de-CH` culture. Native read-aloud offers Swiss-region voices for this choice, while generic German retains its existing regional voice choices. OpenAI read-aloud receives the Swiss culture too. Translation instructions preserve regional/dialect wording already present in recognized input; output into German (Switzerland) uses Swiss Standard German spelling, not a promised dialect transcription or dialect voice. Apple recognition quality for individual Swiss German dialects requires an iPhone test. Image translations retain the selected regional identifier; an unambiguous generic German OCR code is mapped to the Swiss participant, keeping speaker switching and bubble direction correct. Ambiguous regional matches are not guessed.

## Optional OpenAI voice

The setup page uses explicit dark foreground colors on its light background, including labels, key input and voice selection, so system dark mode cannot turn instructional text white. **Settings → OpenAI voice · Off/On** opens an English setup page with an on/off switch, a cost-confirmation dialog, a masked API-key field, and Marin, Cedar or Coral voice selection. It explains API billing step by step and links directly to [API billing](https://platform.openai.com/settings/organization/billing/overview), [key creation](https://platform.openai.com/api-keys), and [current prices](https://developers.openai.com/api/docs/pricing). The user must save the settings; dismissing the page leaves the existing setting unchanged. Removing the saved key disables the feature immediately. No paid request is sent merely by enabling or saving.

OpenAI voice is off by default and uses the user's separately configured API account, never the ChatGPT OAuth token. Each user supplies their own key on their own device; the key is stored only through MAUI SecureStorage (iPhone Keychain), never in preferences, source code, logs or the IPA. No developer-owned key is embedded or distributed. This version does not provide a shared developer-funded voice backend. API credit/model access must be configured by the user. The existing ChatGPT sign-in and translation requests are unchanged. The selected message text is sent to OpenAI only when a speaker icon is tapped; a visible disclosure identifies the voice as AI-generated. Turning the setting off returns to native iPhone speech.

Speech uses `gpt-realtime-2.1-mini` through the public Realtime WebSocket API, as recommended for new speech integrations in the [OpenAI speech guide](https://developers.openai.com/api/docs/guides/text-to-speech). It sends text with verbatim-reading instructions and receives 24 kHz mono PCM; there is no microphone upload. Audio is buffered in memory and played only after a successful completed response, so playback starts after generation completes. Realtime speech follows instructions rather than a strict verbatim guarantee; pronunciation and fidelity need a real-device check. Text is capped at 3,000 characters, generated audio at three minutes, and each request at 90 seconds. Errors and incomplete responses do not play partial audio, and requests are not retried automatically. Generated audio may incur charges even if cancelled. Tapping the same speaker stops a pending request or playback; recording, sending, discarding, leaving the chat or deactivating the app also stops speech. Audio is not persisted. Native audio data and an explicit delegate stay alive until playback cleanup; finish/error callbacks enqueue cleanup on the main queue rather than disposing native objects within a callback. A generation guard prevents an older queued completion from stopping a new player. The feature requires internet; failures are reported rather than silently choosing another paid service or switching voices.

Validation: shared protocol checks cover session setup, fragmented events, WAV output, cancellation, invalid input, incomplete/error replies and redaction. The new native classes were compiled against iOS reference assemblies on Windows. Live API generation, sound quality, iPhone audio routing and UI behavior still require a TestFlight test with the user's key. Windows playback remains unsupported.

## Model selection

A compact model picker in the chat header lists the connected ChatGPT account's visible models, displaying server-provided names while sending their model IDs to the Responses API. The choice is saved locally and applies to the next translation. Selection is disabled while processing or recording a turn. The account-specific catalog is cached for 30 minutes and refreshed on credential changes; signing out clears it. Stored choices absent from a freshly loaded catalog reset to its first entry in the picker; if a model disappears before a request, that request reports an error instead of silently substituting a different model. Model capabilities, account limits and response speed can vary.
## Read aloud and voices

Speaker icons beside original and translated text use native iPhone speech synthesis. Tap the same speaker again to stop; starting recording, discarding input or leaving the page stops playback. Playback is blocked during active recording. **Settings → Speech voices** lets users choose a language, select an available voice and hear a sample greeting; selections are saved per language. The number of voices depends on the installed/available iOS voices, so two or three choices are not guaranteed for every recognition language. The app offers the currently available iPhone voices; it no longer contains an iPhone Settings link or an Add iPhone voices menu item. If a voice is unavailable, it suggests the optional OpenAI voice setting. Speech synthesis uses a system-managed audio session independent of recording. The Windows development build displays an unsupported notice. Native audio routing and voice selection require TestFlight testing.
## Grammar correction on send

Spoken and typed messages are lightly corrected for grammar, spelling and punctuation within the same translation request. The corrected input is displayed and copied as the original-language message, and its transliteration matches that corrected text. Instructions preserve meaning, tone, names, negation, numbers and facts and retain ambiguous wording rather than guessing. Image OCR remains a faithful transcript. No extra API request is added, although returning the corrected text adds output. Correction quality requires real-device testing. On failure or cancellation the unmodified editable draft is retained unless explicitly discarded.
## Current input

The red **× Discard input** button stops recording, cancels an in-progress translation and deletes the current editable draft and attachment. Existing translated chat messages and the selected speaker remain unchanged. Late recognition results cannot restore discarded text. **Cancel** remains available for operations without a draft, such as signing in.

## Conversation languages

Translation responses appear progressively in a temporary preview, then become chat messages only after the complete response has been validated. Cancelling or failing a request removes the preview and retains the original draft and attachment. The model catalog is cached in memory for 30 minutes, scoped to the current credential and cleared after access/model errors; subsequent sends avoid fetching the model catalog again.

The app interface is in English. Open **••• → Settings → Conversation languages** to search and select two different languages. On iPhone, the list is built from `SFSpeechRecognizer.SupportedLocales`, normalized to .NET cultures and grouped by language; the count depends on iOS support. Regional duplicates are combined, preferring the existing recognition locales where available. Some languages require Apple's online recognition service; supported does not guarantee availability at that moment. The Windows development fallback retains English, Spanish, German, German (Switzerland), Japanese and Mandarin. The default pair is English/Japanese where supported and the selection is saved on the device. Speech recognition uses the active language; sending a message translates to the other selected language and switches speakers without starting the microphone. Image text is translated separately between the selected languages. Settings now offers Show/Hide transliteration for all languages. Original and translated non-Latin text receive independent Latin-script readings (for example Japanese Hepburn, Mandarin Pinyin with tones, or Korean romanization). Latin-script text has no extra reading. The previous Romaji preference is retained on upgrade. When disabled, new requests ask for empty transliteration fields; enabling it later cannot add readings to past messages generated without them. Native iOS discovery and individual language quality require device testing.
# Koe – .NET MAUI

Gesprächsübersetzer für Deutsch und Japanisch, jetzt in C# mit .NET MAUI 10.

## Projektstruktur

- `Koe-Maui/`: aktive iPhone-App und Windows-Version für die Entwicklung.
- `Koe-iOS/`: bisheriger SwiftUI-Prototyp als unveränderte Referenz; wird vom Root-Workflow nicht mehr gebaut.
- `codemagic.yaml`: Cloud-Builds für die neue .NET-Version.
- `tests/Koe.CoreChecks/`: ausführbare Tests für Streaming, ID-Token-Verifikation, Umschrift-Antworten und Aufnahme-/Pausenzustände, ohne Apple-Konto oder API-Aufrufe.

## Funktionen

Deutsch ↔ Japanisch als hellblauer Messenger mit Texteingabe und iPhone-Diktat. Unten liegt ein gemeinsam zentriertes Knopfpaar: links das große Mikrofon, rechts der kleinere Sendepfeil (56 × 56 Punkte). Der Mikrofonknopf startet die Aufnahme, pausiert sie beim zweiten Druck und setzt sie beim nächsten Druck fort. Er übersetzt nicht. Erst der separate Sendepfeil beendet eine laufende Aufnahme, wartet auf die letzten erkannten Wörter und übersetzt den gesamten Entwurf einschließlich eines ausgewählten Bilds. Nach erfolgreichem Senden wechselt die Sprache automatisch; die nächste Person startet ihr Mikrofon selbst. Die separaten Pause- und Gespräch-beenden-Knöpfe entfallen.

Das Plus sitzt im Textfeld auf Höhe der ersten Textzeile, auch bei mehrzeiligem Text. Zum Korrigieren ins Textfeld tippen; dabei pausiert die Aufnahme. Markieren, Löschen und Einfügen bleiben verfügbar. Während der Verarbeitung liegt die Ladeanzeige über dem Mikrofonknopf. Über die Lautsprechersymbole ist Sprachausgabe verfügbar; siehe die aktuellen Abschnitte oben. Der Verlauf wird pro Gespräch dauerhaft gespeichert und ist über die Chatliste wieder verfügbar. Einzelne Chats werden dort mit einem Wisch nach links und Delete gelöscht. Auf Windows ist Texteingabe verfügbar; das Diktat ist iOS-spezifisch.

Die ChatGPT-Anmeldung verwendet den dokumentierten Open-Source-SIWC-Flow mit PKCE, State, Nonce, Loopback-Callback und RS256-ID-Token-Verifikation. Tokens liegen in MAUI SecureStorage (auf iOS im Schlüsselbund). Es wird kein API-Schlüssel eingebaut. Optional kann der Nutzer für die kostenpflichtige OpenAI-Sprachausgabe seinen eigenen Schlüssel im Schlüsselbund hinterlegen. Übersetzungen verwenden ein vom Konto angebotenes Modell und die öffentliche Responses API mit `store=false` und `stream=true`. Es werden erkannte bzw. eingegebene Texte und ausdrücklich ausgewählte Bilder an OpenAI geschickt. Audioaufnahmen werden nicht an OpenAI geschickt. Apples Spracherkennung kann je nach Gerät und Sprache Apples Server nutzen.

## Nachrichten und Darstellung

Neue Nachrichten werden automatisch ins Bild gescrollt. Unter Originalen und Übersetzungen mit nichtlateinischer Schrift steht bei aktivierter Einstellung die passende lateinische Umschrift. Die Kopiersymbole neben Original und Übersetzung kopieren jeweils nur diesen Text, ohne Umschrift oder Sprachbezeichnung. Unter **••• → Einstellungen** ist die Textgröße **Klein / Mittel / Groß** wählbar; die Einstellung wirkt sofort und bleibt auf dem Gerät gespeichert.

## Bilder mit einer Nachricht übersetzen

Über **+** am Textfeld ein Foto, die Kamera oder eine Bilddatei auswählen. Pro Nachricht ist ein Bild möglich. Die Vorschau lässt sich mit **×** entfernen. Danach sprechen, schreiben oder das Bild direkt mit **↑** senden. Bildtext und Nachricht werden zusammen verarbeitet, aber als getrennte Sprechblasen angezeigt: Ein japanischer Bildtext wird ins Deutsche übersetzt, ein deutscher ins Japanische. Deine gesprochene Nachricht behält die gewählte Sprechrichtung. Umschrift und Kopieren funktionieren für beide Ergebnisse. Bei Fehlern bleibt der Entwurf samt Bild erhalten.

Auf iOS bereitet UIKit Fotos einschließlich HEIC als JPEG mit maximal 2560 Pixeln längster Kante auf. Die Ausgangsdatei darf höchstens 20 MB und das vorbereitete Bild höchstens 8 MB groß sein. Unter Windows sind JPEG, PNG und WebP unterstützt. Ausgewählte Bilder werden mit dem lokalen Chat bzw. Entwurf gespeichert und erst beim Senden an OpenAI übertragen. Es gibt keinen separaten Files-API-Upload. Kamerazugriff, Fotoauswahl, HEIC/Orientierung und echte Bildübersetzungen müssen noch auf dem iPhone getestet werden.

## Unter Windows entwickeln

1. .NET SDK **10.0.402** und Visual Studio mit .NET MAUI oder VS Code mit C#/.NET-MAUI-Erweiterungen installieren.
2. Im Repo-Root `dotnet workload install maui-windows --version 10.0.402.1` ausführen.
3. `dotnet build Koe-Maui/Koe.csproj -f net10.0-windows10.0.19041.0`.
4. `dotnet build Koe-Maui/Koe.csproj -t:Run -f net10.0-windows10.0.19041.0`.

Tests: `dotnet run --project tests/Koe.CoreChecks/Koe.CoreChecks.csproj -c Release`.

Die iOS-App wird auf einem Mac kompiliert. Ein Windows-PC oder eine Windows-VM genügt zum Bearbeiten und zum Windows-Test; er ersetzt keinen Mac für den iOS-Simulator oder iOS-Debugging.

## Codemagic

Die Konfiguration erwartet SDK 10.0.402, Workload-Set 10.0.402.1 und Xcode 27.1. Diese Versionen gehören zusammen; nicht unabhängig auf `latest` umstellen.

1. Änderungen ins verbundene GitHub-Repo übernehmen.
2. Zuerst **Koe iOS compile check (no signing)** starten. Dieser Workflow kompiliert für den iOS-Simulator ohne Apple-Signierungsdateien. Er veröffentlicht keine App und ist kein iPhone-Laufzeittest.
3. Für **Koe iOS TestFlight** die Integration exakt **webflow** nennen. Apple-Distribution-Zertifikat mit privatem Schlüssel und ein gültiges App-Store-Profil für **ch.paulo.koe** in Codemagic hinterlegen. Die API-Verbindung allein erzeugt diese Dateien nicht.
4. App-ID und App-Store-Connect-App-Datensatz für `ch.paulo.koe` müssen vorhanden sein.
5. **Koe iOS TestFlight** baut die IPA und lädt sie nach App Store Connect. Die Buildnummer wird aus Codemagics BUILD_NUMBER + 1 gebildet; sie muss höher sein als bereits hochgeladene Builds. Bei bestehender App gegebenenfalls die Buildnummerierung in Codemagic erhöhen.

## Noch auf einem echten iPhone zu prüfen

Ein erfolgreicher Compile-Check genügt nicht für die Freigabe: Starten, Mikrofon-/Sprachberechtigungen, Diktat in beiden Sprachen, Login-Abbruch, Loopback-/Browser-Rückkehr, Token-Erneuerung, Abmelden, Übersetzung, Sprecherwechsel und Gespräch beenden müssen auf einem iPhone getestet werden. SIWC ist eine Vorschau; insbesondere der Loopback-Browser-Flow auf iOS ist ein zu verifizierender Integrationspunkt. Kontoberechtigung und Plan-Verfügbarkeit hängen von OpenAI ab.
